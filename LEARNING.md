# Задания для практики (пишешь сам, я проверяю)

Порядок такой: от простого к сложному. Каждое задание делай в отдельной ветке, потом открывай PR в этот репозиторий. Готовность проверяем так: `npm test` зелёный и `npx tsc --noEmit` без ошибок.

## Уровень 1: API

1. **`/api/rate`.** Ответ 200 без входа, в нём есть `rate` (число > 0) и `source`. *Подсказка:* фикстура `api`.
2. **Устройства.** `GET /api/devices` у `newUser` возвращает ровно одно устройство, и его `id` равен `current`.
3. **Отзыв устройства.** Войди вторым контекстом, удали его через `DELETE /api/devices/:id` и убедись, что эта сессия получает 401.
4. **Инвайты.** Обычный (не админ) пользователь пытается открыть `/api/admin/...`. Какой статус ожидать? Узнай по коду `lib/admin.js` и напиши тест.

## Уровень 2: UI + Page Object

5. **`WorkPage`.** Создай Page Object для раздела «Работа»: кнопка «+ Задача», модалка, колонка канбана. Тест: создать задачу и проверить, что она появилась в колонке «To do».
6. **Быстрая задача с Главной.** Нажми `#qTask` и создай задачу, а результат проверь через API (`getStore('work')`).
7. **Темы.** Кнопка темы в сайдбаре переключает Авто → Светлая → Тёмная. Проверь атрибут `data-mode` на `<html>`.
8. **Параметризация.** Тест входа с разными неверными данными: пустой email, пустой пароль, чужой email. Подумай про лимит 8 неудачных попыток за 15 минут с одного IP.

## Уровень 3: архитектура

9. **Фикстура `workPage`** в `src/fixtures/test.ts` по образцу `homePage`.
10. **Теги.** Добавь `@regression` к остальным тестам и скрипт `npm run test:regression`.
11. **Визуальный тест.** `toHaveScreenshot()` для «Качества» на фиксированных данных (`sampleRun`). Разберись, почему нужен `reducedMotion` и фиксированная дата.
12. **Нестабильный тест нарочно.** Напиши тест с `waitForTimeout(200)`, прогони `--repeat-each=20` и посмотри его в MyDesk → «Качество → Тесты». Потом почини его через web-first assertion.

## Уровень 4: CI

13. **Секрет.** Создай fine-grained token и добавь его в секрет `MYDESK_REPO_TOKEN`, затем добейся зелёного запуска в Actions.
14. **Шардирование.** Раздели прогон на 2 шарда (`--shard=1/2`) через `matrix`.
15. **Allure в GitHub Pages.** Публикуй Allure-отчёт после каждого прогона на `main`.
